# 6.3 Pembahasan

Bagian ini membahas secara menyeluruh temuan-temuan dari pengujian model, mengaitkannya dengan karakteristik data yang telah diidentifikasi pada Bab IV, serta menginterpretasikan implikasinya terhadap tujuan penelitian.

## 6.3.1 Peningkatan Signifikan melalui Poisson Objective dan Recency Features

Temuan paling signifikan dari penelitian ini adalah peningkatan MAE sebesar 44% — dari 1,29 menjadi 0,78 cangkir — yang dicapai melalui dua perubahan fundamental: (1) objective `count:poisson` yang sesuai secara matematis untuk data count dengan zero-inflation, dan (2) fitur recency (`Days_Since_Last_Sale`, `Sales_Last_7D`) yang menangkap sinyal paling prediktif pada data kafe skala kecil.

**Poisson vs regresi standar.** Regresi standar (MSE) mengasumsikan residual Gaussian — tidak sesuai untuk data yang 64% bernilai nol dan 50% bernilai tepat 1. Objective Poisson memodelkan probabilitas setiap nilai secara eksplisit: P(Y=0) = e^(-λ) untuk hari tanpa penjualan, dan P(Y=k) = λ^k e^(-λ) / k! untuk k>0. Ini memungkinkan model membedakan antara "item tidak akan terjual hari ini" (λ ≈ 0) dan "item akan terjual 1-2 cangkir" (λ ≈ 1-2) — perbedaan yang hilang pada regresi standar.

**Recency sebagai sinyal dominan.** Feature importance model menempatkan `Days_Since_Last_Sale` pada peringkat pertama dengan bobot 0,73 — 6× lebih tinggi dari fitur berikutnya (EWMA_28: 0,12). Ini mengonfirmasi temuan EDA bahwa pada kafe skala kecil, pertanyaan paling prediktif bukanlah "berapa banyak yang akan terjual?" melainkan "apakah item ini akan terjual sama sekali hari ini?" Recency menjawab pertanyaan pertama, dan sisanya — kuantitas — relatif mudah diprediksi begitu kita tahu item akan terjual (rata-rata 2,4 cangkir pada hari non-nol).

## 6.3.2 Mengapa Single Model Global Lebih Efektif

Pendekatan model global tunggal (satu XGBoost untuk seluruh 61 item) mengungguli pendekatan per-item dan ensemble dalam beberapa aspek:

**Berbagi informasi antar item.** Item dengan data terbatas (21-78 hari) tidak dapat melatih model per-item yang andal. Model global memanfaatkan pola dari item volume tinggi — misalnya, hubungan antara `Days_Since_Last_Sale` dan probabilitas penjualan konsisten di seluruh item, sehingga item baru langsung mendapat manfaat dari pola ini.

**Tidak memerlukan blending.** Ensemble XGBoost + Random Forest + baseline DOW memerlukan tuning 4 parameter blending tambahan dan menambah kompleksitas tanpa perbaikan berarti. Ablasi menunjukkan bahwa menambahkan DOW baseline justru menurunkan performa (MAE +7%). Model Poisson tunggal mencapai akurasi yang sama tanpa kompleksitas tambahan.

**Generalisasi ke item baru.** Ketika item baru ditambahkan ke menu, model global dapat langsung memprediksi tanpa pelatihan ulang — cukup tambahkan one-hot encoding untuk item tersebut. Model per-item akan memerlukan data minimal 60+ hari sebelum dapat digunakan.

## 6.3.3 Keterbatasan Prediktabilitas Data Penjualan Kafe Skala Kecil

Meskipun terjadi peningkatan signifikan, batas fundamental prediktabilitas tetap ada. Tiga indikator independen mengonfirmasi hal ini:

1. **Error Std = 1,37 ≈ mean demand (1,61).** CV≈0,86 berarti ketidakpastian hampir setara dengan sinyal. Pada rasio ini, tidak ada metode peramalan — ARIMA, deep learning, atau ML — yang dapat secara dramatis mengungguli model saat ini.

2. **MAPE 61% (median).** Untuk item dengan rata-rata 1-3 cangkir, satu cangkir error sudah 33-100%. MAPE tinggi bukan indikasi kegagalan model, melainkan sifat struktural dari denominator kecil.

3. **R² 0,55 — 45% varians tidak dapat dijelaskan.** Varians yang tidak dapat dijelaskan berasal dari faktor eksternal (cuaca, event lokal, keberadaan kelompok pelanggan) yang tidak tercakup dalam data historis.

**Implikasinya:** MAE 0,78 adalah ceiling yang dapat dicapai dengan data yang tersedia. Perbaikan lebih lanjut memerlukan data eksternal (misalnya, data cuaca, kalender event), bukan penyempurnaan model.

## 6.3.4 Buffer Newsvendor sebagai Jembatan ke Operasional

Salah satu kontribusi praktis adalah integrasi buffer newsvendor yang diturunkan dari distribusi error model, bukan dari variasi penjualan historis. Pendekatan ini:

1. **Menggunakan error_std (1,37), bukan sales_std (~4,1).** Sales_std mencampur variasi predictable (pola DOW) dengan unpredictable (noise). Error_std hanya mengukur komponen unpredictable — menghasilkan buffer yang lebih kecil dan lebih tepat.

2. **Service level ditentukan oleh biaya operasional.** Critical ratio = margin / (margin + spoilage). Dengan parameter default (margin=3× spoilage), CR=75% → buffer 384 cangkir/minggu. Jika stockout 5× lebih mahal, buffer naik ke 624 cangkir. Ini memberi pemilik kafe kontrol langsung atas trade-off biaya vs risiko.

3. **Buffer per item disesuaikan.** Kopi Susu Husgendam Ice (error_std=3,5) mendapat buffer 2,8 cangkir/hari; Taro Hot (error_std=0,1) mendapat 0,1 cangkir/hari. Total buffer mingguan 384 cangkir — 36% dari permintaan — angka yang masuk akal untuk operasional kafe.

## 6.3.5 Peramalan Multi-Hari dan Akumulasi Error

Peramalan rekursif 7 hari menghadapi trade-off fundamental: menggunakan fitur aktual (statis) menghasilkan MAE terbaik (0,71) tetapi tidak praktis karena fitur aktual tidak tersedia untuk hari masa depan; menggunakan fitur yang diperbarui dengan prediksi (rekursif penuh) mendegradasi MAE ke 1,67 karena akumulasi kesalahan. Pendekatan hibrida — fitur rolling/lag dibekukan, recency diperbarui — mencapai keseimbangan pada MAE 1,29.

Pendekatan ini didasarkan pada observasi bahwa fitur rolling/lag (EWMA, Roll_Mean) sangat sensitif terhadap akumulasi error — satu prediksi buruk merambat ke seluruh perhitungan rolling. Sebaliknya, fitur recency (Days_Since_Last_Sale) bersifat diskrit dan tidak terakumulasi — hanya peduli "kapan terakhir kali terjual?" Biaya komputasi pembaruan recency adalah O(1) per item, jauh lebih ringan daripada O(window_size) untuk rolling.

**Weekend recency reset** adalah inovasi kecil dengan dampak besar. Tanpa reset, item yang kebetulan absen pada hari jangkar (hari terakhir data aktual) akan diprediksi 0 untuk seluruh horizon 7 hari — terlepas dari hari apa. Dengan reset pada Jumat/Sabtu/Minggu, item "dibangkitkan kembali" pada akhir pekan ketika traffic kafe lebih tinggi. Ini adalah contoh bagaimana pengetahuan domain (akhir pekan = traffic tinggi) dapat diintegrasikan ke dalam pipeline ML tanpa mengubah arsitektur model.

## 6.3.6 Keterbatasan dan Arah Pengembangan

**Keterbatasan:**
1. **Selasa/Kamis anomaly.** MAPE Selasa (79%) dan Kamis (76%) secara konsisten lebih tinggi — kemungkinan terkait jadwal operasional kafe (hari pengiriman/restock) yang tidak tercakup dalam fitur.
2. **Fitur eksternal.** Faktor cuaca, hari libur, dan event lokal tidak dimasukkan — berpotensi meningkatkan R² di atas 0,55.
3. **Item intermiten.** Dua item (Filter, Taro Hot) memiliki zero-inflation >80% dan mungkin lebih cocok dengan metode Croston, namun volumenya sangat kecil sehingga dampaknya minimal.
4. **Generalisasi hyperparameter.** Tuning dilakukan pada seluruh item sekaligus — item individual mungkin mendapat manfaat dari tuning terpisah, namun perbaikannya diperkirakan minimal (<1%).

**Arah pengembangan:**
1. **Integrasi data eksternal** (cuaca, kalender event) untuk menangkap 45% varians yang saat ini tidak dapat dijelaskan.
2. **Deteksi anomali otomatis** untuk mengidentifikasi dan menandai hari Selasa/Kamis yang tidak normal — memungkinkan operator kafe melakukan penyesuaian manual.
3. **Monitoring drift** — control chart MAE mingguan; jika MAE > 1,2 selama 2 minggu berturut-turut, retrain model.
4. **Feedback loop operasional** — mencatat kapan prediksi meleset dan penyebabnya (restock day, event khusus) untuk meningkatkan akurasi fitur di masa depan.
