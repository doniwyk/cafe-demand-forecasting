Sub-bab ini menyajikan implementasi pipeline peramalan yang dibangun berdasarkan perancangan pada Sub-bab 4.4. Setiap tahap perancangan di Bab IV diimplementasikan dalam skrip `forecast.py` yang berfungsi sebagai *entry point* produksi. ## 5.1.1 Arsitektur Pipeline

Pipeline dirancang dalam **dua fase terpisah**: fase pelatihan (training) yang menghasilkan model tersimpan, dan fase inferensi (prediction) yang menggunakan model tersimpan untuk prediksi on-the-fly tanpa pelatihan ulang.

**Fase 1 — Pelatihan.** Menjalankan keseluruhan alur preprocessing, rekayasa fitur, pelatihan XGBoost, dan hyperparameter tuning. Output fase ini adalah file model `forecast_model_xgb.pkl` yang berisi model terlatih beserta seluruh parameternya — siap digunakan untuk inferensi tanpa perlu mengakses data historis lengkap atau melatih ulang.

**Fase 2 — Inferensi.** Memuat model dari `forecast_model_xgb.pkl`, menginisialisasi `Forecaster` dengan data historis 60 hari terakhir untuk konteks recency dan lag, dan melakukan peramalan multi-hari menggunakan strategi fitur hibrida. Inferensi bersifat on-the-fly: setiap kali prediksi dibutuhkan (misalnya mingguan untuk pemesanan bahan baku), pipeline hanya perlu memuat model dan data terkini dari `hus_db` — tanpa melalui tahap pelatihan.

Pipeline menggunakan **model global tunggal** yang memproses 61 item secara bersamaan, konsekuensi dari zero-inflation 64% dan 16 item baru dengan data terbatas (Sub-bab 4.4.2.3 dan 4.4.2.6).

## 5.1.3 Implementasi Rekayasa Fitur

Merujuk pada perancangan Sub-bab 4.4.3, 31 fitur final diimplementasikan dalam fungsi `build_features()`. Seluruh fitur mengikuti prinsip past-only dengan `shift(1)`.

### 5.1.3.1 Recency dan Lag Features

Recency adalah kelompok fitur paling kritis (Δ MAE +0,517). Kode Program 5.2 menunjukkan implementasi `Days_Since_Last_Sale` dan `Sales_Last_7D` melalui iterasi backward per item.

**Kode Program 5.2 Konstruksi Fitur Recency dan Lag per Item**

```python
full = full.sort_values(["Item","Date_Only"]).reset_index(drop=True)
for item in items:
    m = full["Item"]==item; idxs = full[m].index
    q = full.loc[m,"Quantity"].values; n = len(q)

    # Recency: Days_Since_Last_Sale + Sales_Last_7D
    days_since = np.full(n, 999, dtype=int)
    s7d = np.zeros(n, dtype=int); last = None
    for i in range(n):
        if q[i] > 0: last = i
        if last is not None: days_since[i] = min(i-last, 999)
        s7d[i] = int(sum(1 for j in range(max(0,i-7),i) if q[j]>0))
    full.loc[m,"Days_Since_Last_Sale"] = days_since
    full.loc[m,"Sales_Last_7D"] = s7d

    # Lags: nilai aktual k hari lalu
    s = pd.Series(q)
    full.loc[m,"Lag_1"]  = s.shift(1).fillna(0).values
    full.loc[m,"Lag_7"]  = s.shift(7).fillna(0).values
    full.loc[m,"Lag_14"] = s.shift(14).fillna(0).values
    full.loc[m,"Lag_28"] = s.shift(28).fillna(0).values
```

Iterasi backward pada Days_Since_Last_Sale: array diinisialisasi 999 (sentinel), untuk setiap hari *i*, jika ada penjualan (`q[i] > 0`), indeks `last` diperbarui, dan selisih `i - last` menjadi nilai recency. `Sales_Last_7D` menghitung jumlah hari dengan penjualan dalam 7 hari sebelum *i*. Kedua fitur tidak menyertakan hari *i* itu sendiri ,  memenuhi prinsip past-only.

### 5.1.3.2 Cross-Item Features

Merujuk pada perancangan Sub-bab 4.4.3.2F, fitur cross-item menggunakan agregat harian kemarin melalui `shift(1)`. Kode Program 5.3 menunjukkan implementasinya.

**Kode Program 5.3 Konstruksi Fitur Cross-Item**

```python
# Agregat harian kemarin (shift 1 = past-only)
daily = full.groupby("Date_Only").agg(
    Total_Qty=("Quantity","sum"),
    Total_Items_Sold=("Is_Sale","sum")).shift(1).fillna(0)
daily["Total_Beverage"] = full[full["Category"]=="beverage"].groupby(
    "Date_Only")["Quantity"].sum().shift(1).fillna(0)
daily["Total_Food"] = full[full["Category"]=="food"].groupby(
    "Date_Only")["Quantity"].sum().shift(1).fillna(0)
daily["Total_Qty_7D"] = daily["Total_Qty"].rolling(7,min_periods=1).mean()

for col in ["Total_Qty","Total_Items_Sold","Total_Beverage",
            "Total_Food","Total_Qty_7D"]:
    full[f"Day_{col}"] = full["Date_Only"].map(daily[col]).fillna(0)
```

`shift(1)` memastikan fitur untuk hari *t* menggunakan total kafe hari *t*−1. `rolling(7)` pada `Total_Qty` memberikan rata-rata 7-hari sebagai konteks level kesibukan normal.

## 5.1.5 Simulasi Perhitungan Manual XGBoost

Untuk memvalidasi alur logika algoritma XGBoost yang diimplementasikan, dilakukan simulasi perhitungan manual menggunakan data aktual dari dataset Cafe Husgendam. Simulasi ini menggunakan 4 baris data item Tubruk dari periode 1–4 Januari 2026, dengan 3 fitur: `Days_Since_Last_Sale` ($X_1$), `Sales_Last_7D` ($X_2$), dan `DOW_Avg` ($X_3$). Parameter model: `max_depth` = 2, *learning rate* $\alpha$ = 0,3, regularisasi $\lambda$ = 0.

|:--:|:--------|:---:|:---:|:---:|:-----:|:---:|
| 1 | 2026-01-01 | Kamis | 0 | 6 | 3,82 | 4 |
| 2 | 2026-01-02 | Jumat | 1 | 6 | 3,19 | 0 |
| 3 | 2026-01-03 | Sabtu | 0 | 5 | 4,24 | 4 |
| 4 | 2026-01-04 | Minggu | 0 | 5 | 3,86 | 4 |

Data 1, 3, 4: Tubruk terjual 4 cangkir pada hari dengan `Days_Since_Last_Sale` = 0 (baru terjual). Data 2: Tubruk TIDAK terjual pada hari Jumat (`Days_Since_Last_Sale` = 1, tidak terjual kemarin). `DOW_Avg` data 2 (3,19) jauh lebih rendah dari data lainnya (3,82–4,24) — mencerminkan bahwa Jumat secara historis adalah hari dengan penjualan terendah.

#### Langkah 1: Inisialisasi Prediksi Awal ($f^{(0)}$)

Prediksi awal dalam count space adalah rata-rata dari seluruh target. Untuk objective `count:poisson` dengan default `base_score`, XGBoost menginisialisasi raw score sebagai log dari rata-rata target:

$$\hat{y}^{(0)} = \frac{\sum y_i}{n} = \frac{4 + 0 + 4 + 4}{4} = \frac{12}{4} = 3,0$$

$$f^{(0)} = \ln(\hat{y}^{(0)}) = \ln(3,0) \approx 1,099$$

Keduanya ekuivalen: $\hat{y}^{(0)} = \exp(f^{(0)}) = \exp(1,099) = 3,0$.

#### Langkah 2: Perhitungan Gradien dan Hessian (Iterasi 1)

Untuk Poisson loss, gradien dan Hessian dihitung terhadap raw score $f$:

$$g_i = \exp(f_i) - y_i, \quad h_i = \exp(f_i)$$

Pada iterasi pertama, $\exp(f_i^{(0)}) = \hat{y}^{(0)} = 3,0$, sehingga:

**Tabel 5.7 Perhitungan Gradien dan Hessian Awal**

| No | $y$ | $\hat{y}^{(0)}$ | $g_i = \hat{y}^{(0)} - y$ | $h_i = \hat{y}^{(0)}$ |
|:--:|:---:|:-----------:|:---------------------:|:-----------------:|
| 1 | 4 | 3,0 | −1,0 | 3,0 |
| 2 | 0 | 3,0 | +3,0 | 3,0 |
| 3 | 4 | 3,0 | −1,0 | 3,0 |
| 4 | 4 | 3,0 | −1,0 | 3,0 |
| **Total** | | | $G = 0,0$ | $H = 12,0$ |

Gradien negatif (−1,0) pada data 1, 3, 4: model perlu meningkatkan prediksi (karena 3,0 < 4). Gradien positif (+3,0) pada data 2: model perlu menurunkan prediksi secara signifikan (karena 3,0 jauh di atas 0). Total G = 0 karena gradien saling meniadakan — wajar karena $\hat{y}^{(0)}$ adalah rata-rata target.

#### Langkah 3: Pembentukan Pohon Kedalaman 1 — Perhitungan Gain

Setiap fitur diuji sebagai kandidat *split point*. Gain mengukur perbaikan dari memisahkan data:

$$Gain = \frac{1}{2} \left[ \frac{G_L^2}{H_L + \lambda} + \frac{G_R^2}{H_R + \lambda} - \frac{(G_L + G_R)^2}{H_L + H_R + \lambda} \right] - \gamma$$

dengan $\gamma = 0$, $\lambda = 0$.

**a. Fitur $X_1$ (Days_Since_Last_Sale).** Nilai unik: {0, 1}. $T = 0,5$.

| Simpul | Data ke- | $G$ | $H$ |
|:-------|:--------:|:---:|:---:|
| Kiri ($X_1 < 0,5$) | 1, 3, 4 | $G_L = -3,0$ | $H_L = 9,0$ |
| Kanan ($X_1 \geq 0,5$) | 2 | $G_R = +3,0$ | $H_R = 3,0$ |

$$Gain_{X_1} = \frac{1}{2} \left[ \frac{9,0}{9,0} + \frac{9,0}{3,0} - 0 \right] = \frac{1}{2} [1,0 + 3,0] = 2,00$$

**b. Fitur $X_2$ (Sales_Last_7D).** Nilai unik: {5, 6}. $T = 5,5$.

| Simpul | Data ke- | $G$ | $H$ |
|:-------|:--------:|:---:|:---:|
| Kiri ($X_2 < 5,5$) | 3, 4 | $G_L = -2,0$ | $H_L = 6,0$ |
| Kanan ($X_2 \geq 5,5$) | 1, 2 | $G_R = +2,0$ | $H_R = 6,0$ |

$$Gain_{X_2} = \frac{1}{2} \left[ \frac{4,0}{6,0} + \frac{4,0}{6,0} - 0 \right] = 0,667$$

**c. Fitur $X_3$ (DOW_Avg).** Nilai pada data: data 1 = 3,82, data 2 = 3,19, data 3 = 4,24, data 4 = 3,86. Diurutkan: [3,19, 3,82, 3,86, 4,24]. Tiga kandidat threshold: $T_1 = 3,505$, $T_2 = 3,84$, $T_3 = 4,05$.

$T = 3,505$ memberikan Gain terbaik:

| Simpul | Data ke- | $G$ | $H$ |
|:-------|:--------:|:---:|:---:|
| Kiri ($X_3 < 3,505$) | 2 | $G_L = +3,0$ | $H_L = 3,0$ |
| Kanan ($X_3 \geq 3,505$) | 1, 3, 4 | $G_R = -3,0$ | $H_R = 9,0$ |

$$Gain_{X_3} = \frac{1}{2} \left[ \frac{9,0}{3,0} + \frac{9,0}{9,0} - 0 \right] = 2,00$$

($T_2 = 3,84$: Gain = 0,667; $T_3 = 4,05$: Gain = 0,222)

#### Langkah 4: Bobot Daun dan Update Prediksi

Bobot optimal setiap simpul daun:

$$\omega_L^* = -\frac{G_L}{H_L + \lambda} = -\frac{-3,0}{9,0} = 0,333$$

$$\omega_R^* = -\frac{G_R}{H_R + \lambda} = -\frac{+3,0}{3,0} = -1,000$$

XGBoost mengupdate raw score $f$ dalam log-space, bukan prediksi count secara langsung:

$$f^{(t+1)} = f^{(t)} + \alpha \cdot \omega^*, \quad \hat{y}^{(t+1)} = \exp(f^{(t+1)})$$

Dengan $f^{(0)} = \ln(3,0) \approx 1,099$ dan $\alpha = 0,3$:

#### Interpretasi

Setelah satu iterasi, model telah belajar dua pola. Pertama, item dengan `Days_Since_Last_Sale` < 0,5 (data 1, 3, 4 — baru terjual) mendapat koreksi positif: prediksi naik 3,0 → 3,32, mendekati aktual 4. Model mempelajari bahwa item yang baru terjual cenderung terus terjual. Kedua, item dengan `Days_Since_Last_Sale` ≥ 0,5 (data 2 — tidak terjual kemarin) mendapat koreksi negatif signifikan: prediksi turun 3,0 → 2,22, mendekati aktual 0. Model mempelajari bahwa hari dengan recency tinggi cenderung memiliki penjualan rendah atau nol.

Error data 2 berkurang dari |3,0 − 0| = 3,0 menjadi |2,22 − 0| = 2,22. Dalam 200 iterasi penuh, setiap pohon baru dilatih pada residual ensemble sebelumnya, secara bertahap mengoreksi error hingga konvergensi. Pohon berikutnya mungkin memilih $X_2$ atau $X_3$ sebagai split point — setelah recency menangani pemisahan nol vs non-nol, sisa error bisa dijelaskan oleh fitur lain.

Simulasi memvalidasi dua temuan kunci Bab IV. Pertama, $X_1$ (recency) dan $X_3$ (DOW_Avg) sama-sama kuat pada iterasi pertama — keduanya mencapai Gain 2,00 dengan partisi identik; $X_1$ dipilih melalui tie-breaking. Kedua, mekanisme Poisson menangani zero-inflation secara natural — bobot daun negatif ($\omega_R^* = -1,000$) untuk data nol dan positif ($\omega_L^* = +0,333$) untuk data non-nol terjadi otomatis melalui gradien/Hessian Poisson loss, tanpa model klasifikasi terpisah.

## 5.1.6 Implementasi Hyperparameter Tuning

Merujuk pada perancangan Sub-bab 4.4.4.5, tuning diimplementasikan melalui fungsi `compare_models()` pada `forecast.py`. Validasi menggunakan rolling window 3-fold pada 3 minggu terakhir sebelum periode backtest — menjaga urutan temporal, berbeda dengan K-fold cross-validation. Kode Program 5.5 menunjukkan logika inti grid search sekuensial tiga ronde.

**Kode Program 5.5 Grid Search XGBoost**

```python
param_grid = [
    {'max_depth': [3,4,5,6], 'learning_rate': [0.03,0.05,0.1],
     'n_estimators': [200,300]},                          # Ronde 1
    {'subsample': [0.6,0.8,1.0],
     'colsample_bytree': [0.6,0.8,1.0]},                  # Ronde 2
    {'reg_alpha': [0,0.5,1.0,2.0], 'reg_lambda': [0.5,1.0,2.0,5.0],
     'min_child_weight': [1,3,5]},                        # Ronde 3
]

best_mae = float('inf')
best_params = None

for rnd, grid in enumerate(param_grid):
    resolved = {}
    for k, v in grid.items():
        resolved[k] = [best_params.get(k, v[0])] if v == ["best"] else v
    for params in ParameterGrid(resolved):
        maes = []
        for w in range(3):  # 3-fold rolling window
            train = data[data['Date_Only'] < val_start + timedelta(days=7*w)]
            val   = data[(data['Date_Only'] >= val_start + timedelta(days=7*w)) &
                         (data['Date_Only'] <= val_start + timedelta(days=7*w+6))]
            model = XGBRegressor(objective='count:poisson',
                                 random_state=42, verbosity=0, **params)
            model.fit(train[features].fillna(0), train['Quantity'])
            preds = np.maximum(model.predict(val[features].fillna(0)), 0)
            maes.append(mean_absolute_error(val['Quantity'], preds))
        if np.mean(maes) < best_mae:
            best_mae = np.mean(maes)
            best_params = params
```

Setiap ronde menggunakan parameter terbaik ronde sebelumnya sebagai baseline. Parameter yang sudah optimal ("best") dikunci — ronde berikutnya hanya mengeksplorasi parameter baru. Total 81 kombinasi dievaluasi: 24 (ronde 1) + 9 (ronde 2) + 48 (ronde 3).

## 5.1.7 Implementasi Peramalan Multi-Hari

Merujuk pada perancangan Sub-bab 4.4.4 dan strategi fitur hibrida (Sub-bab 5.1.3.2), peramalan multi-hari diimplementasikan melalui kelas `Forecaster`. Kode Program 5.6 menunjukkan metode inti `build()` yang membangun fitur untuk satu hari peramalan.

**Kode Program 5.6 Konstruksi Fitur per Hari Peramalan (Forecaster.build)**

```python
def build(self, date, prev_day=None):
    rows = []; ts = pd.Timestamp(date)
    for item in self.items:
        qty_r = list(self.qty_history.get(item, [0.0]))
        dsl, s7d = self._recency(np.array(qty_r))
        dow = ts.dayofweek
        if dow >= 4: dsl = 0.0; s7d = max(s7d, 1)  # weekend reset
        lags = self._lags(self.frozen_qty.get(item, np.array([0.0])))
        pdv = prev_day or {}
        row = {
            "DOW":dow, "Is_Weekend":1 if dow>=5 else 0,
            "Month":ts.month, "Year":ts.year,
            "WeekOfYear":ts.isocalendar()[1],
            "DayOfMonth":ts.day, "Quarter":(ts.month-1)//3+1,
            "MonthStart":1 if ts.day<=7 else 0,
            "MonthEnd":1 if ts.day>=25 else 0,
            "Is_Holiday_Season":1 if ts.month in(12,1) else 0,
            "WeekOfMonth":(ts.day-1)//7+1,
            "DaysFromStart":(ts-pd.Timestamp("2022-01-01")).days,
            "DOW_Sin":np.sin(2*np.pi*dow/7),
            "DOW_Cos":np.cos(2*np.pi*dow/7),
            "Month_Sin":np.sin(2*np.pi*ts.month/12),
            "Month_Cos":np.cos(2*np.pi*ts.month/12),
            "Days_Since_Last_Sale":dsl, "Sales_Last_7D":s7d, **lags,
            "Day_Total_Qty":pdv.get("total_qty",0),
            "Day_Total_Qty_7D":pdv.get("total_qty_7d",0),
        }
        rows.append(row)
    return pd.DataFrame(rows)
```

Kelas `Forecaster` mengelola dua struktur data: `frozen_qty` ,  tidak diperbarui, untuk menghitung fitur lag yang dibekukan pada data aktual terakhir, dan `qty_history` ,  diperbarui setiap hari dengan prediksi, untuk menghitung fitur recency. Weekend recency reset (baris 7) diaktifkan untuk DOW ≥ 4 (Jumat–Minggu).

Algoritma peramalan untuk setiap hari *d* = 1..7: (1) `Forecaster.build()` membangun fitur 61 item; (2) `model.predict()` menghasilkan prediksi; (3) `Forecaster.update_recency()` memperbarui `qty_history` dengan prediksi; (4) cross-item dihitung ulang dari agregat prediksi. History dibatasi `MAX_WINDOW = 60` hari.

|:---------|:---------|:-----------|

## 5.1.8 Implementasi Buffer Persediaan Newsvendor

Merujuk pada perancangan Sub-bab 4.4.4.7, buffer persediaan dihitung menggunakan model newsvendor. Kode Program 5.7 menunjukkan implementasi fungsi `compute_buffer()`.

**Kode Program 5.7 Perhitungan Buffer Newsvendor**

```python
def compute_buffer(full, items, margin_lost=3, spoilage_cost=1):
    error_csv = os.path.join(TABLES_DIR, "v2_per_item_errors.csv")
    cr = margin_lost / (margin_lost + spoilage_cost)
    z = max(0, min(2.5, (cr - 0.5) * 3.2))  # aproksimasi invers normal

    if os.path.exists(error_csv):
        err_df = pd.read_csv(error_csv)
        for _, r in err_df.iterrows():
            buffers[r["Item"]] = {
                "error_std": round(r["Error_Std"], 3),
                "buffer": round(z * r["Error_Std"], 2),
            }
    else:
        # Fallback: estimasi lag-1 proxy 84 hari terakhir
        TW = 84; cutoff = full["Date_Only"].max() - timedelta(days=TW)
        recent = full[full["Date_Only"] > cutoff]
        for item in items:
            it_data = recent[recent["Item"]==item].sort_values("Date_Only")
            actuals = it_data["Quantity"].values
            naive = np.roll(actuals, 1); naive[0] = 0
            error_std = np.std((naive - actuals)[1:])
            buffers[item] = {"error_std": round(error_std, 3),
                             "buffer": round(z * error_std, 2)}
    return buffers
```

Critical ratio `CR = margin / (margin + spoilage)` menentukan service level optimal. Nilai z diaproksimasi dengan `z = max(0, min(2.5, (CR−0.5)×3.2))` ,  memberikan z ≈ 0 untuk CR=50%, z ≈ 0,67 untuk CR=75%, dan z ≈ 0,96 untuk CR=83%. Buffer per item: `buffer = z × σ_error`. Jika file backtest `v2_per_item_errors.csv` belum tersedia, fallback menggunakan lag-1 proxy: pada 84 hari terakhir, error = `Quantity[t] − Quantity[t−1]`, dan `σ_error` = std dari error tersebut.

| Stockout 3× spoilage | 3 : 1 | 75% | 0,67 | 468 cangkir |
| Stockout 2× spoilage | 2 : 1 | 67% | 0,44 | 312 cangkir |
