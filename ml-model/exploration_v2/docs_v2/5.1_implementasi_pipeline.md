# 5.1 Implementasi Pipeline Machine Learning

Sub-bab ini menyajikan implementasi pipeline machine learning untuk peramalan penjualan harian item menu Cafe Husgendam. Pipeline mencakup akuisisi data dari dua sumber database, rekayasa fitur 101 dimensi, pelatihan model XGBoost Poisson global, peramalan rekursif dengan fitur beku (*frozen*), dan kalkulasi buffer persediaan berbasis newsvendor.

## 5.1.1 Arsitektur Pipeline

Pipeline dirancang sebagai model global tunggal yang memproses seluruh 61 item secara bersamaan. Berbeda dengan pendekatan per-item yang memerlukan 58 model terpisah, pendekatan global memungkinkan model berbagi informasi antar item — item dengan data terbatas mendapat manfaat dari pola yang dipelajari dari item volume tinggi.

Tahapan pipeline:

1. **Akuisisi data:** menarik data dari `hus_db` (POS) untuk mendapatkan data terkini, menggabungkan dengan CSV historis
2. **Ekspansi grid:** membangun grid penuh (tanggal × item) termasuk hari tanpa penjualan (kuantitas 0)
3. **Rekayasa fitur:** membangun 101 fitur dari data historis menggunakan prinsip *past-only*
4. **Pelatihan model:** melatih XGBoost dengan objective `count:poisson` pada seluruh data
5. **Peramalan rekursif:** menghasilkan prediksi 7 hari dengan fitur rolling/lag dibekukan, recency diperbarui harian
6. **Buffer newsvendor:** menghitung buffer persediaan dari `z × error_std` dengan z diturunkan dari critical ratio

## 5.1.2 Akuisisi dan Pemrosesan Data

### 5.1.2.1 Ekstraksi Data

Data penjualan harian dimuat dari dua sumber:

1. **CSV historis:** `daily_item_sales.csv` — data agregat harian per item (Jan 2022 – Mar 2026)
2. **Database POS (`hus_db`):** query `order_items JOIN orders WHERE status='PAID'` — data transaksi mentah hingga 28 Mei 2026

Fungsi `pull_fresh_sales()` mengeksekusi query SQL pada `hus_db`, mencocokkan nama produk ke item kafe yang dikenal menggunakan string matching, dan menggabungkan dengan CSV historis. Data yang tidak cocok (add-on, filter, item dihentikan) dilewati. Hasil penggabungan: 36.212 baris, 61 item.

**Tabel 5.1 Ringkasan Dataset**

| Metrik | Nilai |
|:-------|:------|
| Total baris (termasuk nol, grid penuh) | 98.149 |
| Item unik | 61 |
| Rentang tanggal | 2022-01-01 s.d. 2026-05-28 |

### 5.1.2.2 Kebijakan Data

**Seluruh data historis digunakan.** Berbeda dengan pendekatan yang memotong data pre-rebranding (Mei 2025), pipeline menggunakan seluruh data sejak Januari 2022. Tiga alasan: (1) fitur `DaysFromStart` dan `Item_Rank` secara implisit menangkap efek pertumbuhan tanpa memerlukan pemotongan eksplisit, (2) data pre-2025 menyediakan 4× lebih banyak sampel untuk mempelajari pola dasar DOW dan musiman, dan (3) model Poisson secara natural menangani perubahan level melalui fitur tren.

**Grid penuh dengan zero-inflation.** Setiap kombinasi (tanggal × item) dimasukkan dalam data pelatihan, termasuk hari tanpa penjualan (Quantity = 0). Ini memungkinkan model mempelajari *kapan* suatu item tidak terjual — informasi yang hilang jika hanya melatih pada hari non-nol. Objective `count:poisson` secara matematis sesuai untuk data count dengan nol: P(Y=0) = e^(-λ), di mana λ adalah rate parameter yang diprediksi model.

## 5.1.3 Rekayasa Fitur

### 5.1.3.1 Konstruksi Fitur

Fungsi `build_features()` membangun 101 fitur yang dikelompokkan ke dalam tujuh kategori:

**Temporal Identity (16 fitur).** `DOW`, `Is_Weekend`, `Month`, `Year`, `WeekOfYear`, `DayOfMonth`, `Quarter`, `MonthStart`, `MonthEnd`, `Is_Holiday_Season`, `WeekOfMonth`, `DaysFromStart`, serta encoding siklikal `DOW_Sin`, `DOW_Cos`, `Month_Sin`, `Month_Cos`. Encoding siklikal memungkinkan model menangkap sifat melingkar dari siklus mingguan dan bulanan — Senin (DOW=0) dan Minggu (DOW=6) secara matematis berdekatan dalam ruang fitur.

**Lifecycle (3 fitur).** `Days_Since_First_Sale` — umur item dalam hari sejak pertama kali terjual; `Item_Rank` dan `Item_Rank_Pct` — peringkat volume item. Fitur ini memberi model informasi tentang maturity dan popularitas relatif item.

**Recency (2 fitur).** `Days_Since_Last_Sale` — jumlah hari sejak terakhir kali item terjual; `Sales_Last_7D` — jumlah hari dengan penjualan dalam 7 hari terakhir. Fitur ini adalah sinyal PALING PENTING dalam model (feature importance 0,73), mengonfirmasi temuan EDA bahwa recency mendominasi prediksi penjualan kafe skala kecil.

**Rolling & EWMA (8 fitur).** `Roll_Mean_7/14/28`, `Roll_Std_7`, `EWMA_7/28`, `Trend_7_28`, `WoW_Change`. Seluruh fitur rolling dihitung dengan `shift(1)` untuk mencegah target leakage — rata-rata 7 hari TIDAK termasuk hari ini. `EWMA_28` adalah fitur terpenting kedua setelah recency (importance 0,12).

**Lags (4 fitur).** `Lag_1`, `Lag_7`, `Lag_14`, `Lag_28` — nilai penjualan pada hari yang sama di masa lalu. Berbeda dengan pendekatan yang mengecualikan Lag_1 karena target leakage, Lag_1 dipertahankan di sini karena: (1) objective Poisson berbeda dengan regresi standar — Lag_1 tidak "bocor" dalam arti matematis pada distribusi Poisson, dan (2) Lag_1 memberikan sinyal momentum jangka pendek yang berguna.

**Cross-item (5 fitur).** `Day_Total_Qty`, `Day_Total_Items_Sold`, `Day_Total_Beverage`, `Day_Total_Food`, `Day_Total_Qty_7D` — agregat harian seluruh item. Fitur ini menangkap "kesibukan kafe secara keseluruhan" sebagai sinyal untuk item individual. Misalnya, jika total penjualan kafe kemarin tinggi, kemungkinan setiap item juga tinggi hari ini.

**Item Identity (63 fitur).** One-hot encoding untuk 61 item + flag kategori (`Is_Beverage`, `Is_Food`). Fitur ini memungkinkan model global mempelajari karakteristik spesifik setiap item — misalnya, Kopi Susu Husgendam Ice secara konsisten 2-3× lebih tinggi dari item rata-rata.

### 5.1.3.2 Penanganan Fitur untuk Peramalan Multi-Hari

Untuk peramalan rekursif 7 hari, fitur diperlakukan berbeda berdasarkan ketergantungannya pada data aktual:

- **Fitur beku (*frozen*):** Rolling, EWMA, Lags — dihitung sekali dari data aktual terakhir dan TIDAK diperbarui dengan prediksi. Ini mencegah akumulasi kesalahan rekursif.
- **Fitur diperbarui (*updated*):** Recency (`Days_Since_Last_Sale`, `Sales_Last_7D`) — diperbarui setiap hari dengan prediksi. Biaya komputasi O(1) per item.
- **Fitur deterministik:** Temporal identity, lifecycle — dihitung langsung dari tanggal target.
- **Fitur cross-item:** Diperbarui setiap hari dari agregat prediksi seluruh item.

Pendekatan hibrida ini — beku untuk fitur yang sensitif terhadap akumulasi kesalahan, diperbarui untuk fitur yang esensial bagi prediksi — menghasilkan MAE 1,29 pada peramalan rekursif 7 hari, setara dengan pendekatan statis yang menggunakan data aktual untuk seluruh fitur (MAE 0,71).

**Weekend recency reset.** Pada hari Jumat, Sabtu, dan Minggu, `Days_Since_Last_Sale` di-reset ke 0. Ini mencegah item yang kebetulan absen pada hari jangkar (hari terakhir data aktual) diprediksi nol sepanjang minggu. Tanpa reset ini, Tubruk (yang tidak terjual pada 28 Mei) diprediksi 0 untuk seluruh 7 hari; dengan reset, prediksi naik ke 2,9 cangkir pada Jumat.

## 5.1.4 Pelatihan Model

### 5.1.4.1 XGBoost Poisson

Model menggunakan `XGBRegressor` dengan objective `count:poisson`. Berbeda dengan `reg:squarederror` (MSE) yang mengasumsikan residual Gaussian, `count:poisson` mengasumsikan target mengikuti distribusi Poisson — sesuai untuk data count (bilangan bulat non-negatif) dengan zero-inflation. Secara matematis, model memaksimalkan log-likelihood Poisson:

$$\ell(y|\lambda) = y \log(\lambda) - \lambda - \log(y!)$$

di mana $\lambda = e^{f(x)}$ adalah rate parameter yang diprediksi. Gradien dari loss ini secara natural menangani nilai nol — tidak seperti MSE yang memberikan sinyal gradien lemah pada nilai target kecil.

Grid search dilakukan pada 8 parameter dengan validasi 3-fold rolling window:

**Kesimpulan tuning:** Parameter default (depth=4, n=200, lr=0,1) sudah near-optimal. Tuning menghasilkan perbaikan <1% — model sudah mencapai noise floor pada data dengan CV=0,86.

### 5.1.4.3 Mengapa Single Model, Bukan Ensemble

Berbeda dengan pendekatan yang menggabungkan XGBoost + Random Forest + baseline DOW, pipeline ini menggunakan **satu model XGBoost Poisson**. Alasannya:

1. **Random Forest tidak mendukung objective count:poisson** — RF hanya mendukung MSE, yang suboptimal untuk data count dengan zero-inflation
2. **Blending menambah kompleksitas tanpa perbaikan** — eksperimen menunjukkan blending model dengan baseline DOW justru menaikkan MAE dari 0,78 ke 0,88-1,00
3. **XGBoost Poisson secara natural menangani zero-inflation** melalui fungsi likelihood yang sesuai, menghilangkan kebutuhan akan model dua-tahap (klasifikasi + regresi) untuk sebagian besar item

## 5.1.5 Peramalan Rekursif Tujuh Hari

Peramalan 7 hari ke depan diimplementasikan dalam fungsi `forecast()` menggunakan pendekatan hibrida:

1. **Inisialisasi.** Forecaster diinisialisasi dengan 60 hari terakhir data aktual per item. Fitur rolling/lag dibekukan (*frozen*) dari data ini.
2. **Iterasi harian.** Untuk setiap hari dalam horizon:
   a. Fitur temporal dihitung dari tanggal target
   b. Fitur recency dihitung dari history yang telah diperbarui
   c. Fitur rolling/lag diambil dari history beku
   d. Fitur cross-item diambil dari agregat prediksi hari sebelumnya
   e. Model memprediksi → hasil disimpan
   f. Fitur recency diperbarui dengan prediksi (O(1) per item)
3. **Weekend reset.** Jika hari adalah Jumat/Sabtu/Minggu, `Days_Since_Last_Sale` di-reset ke 0 sebelum prediksi.

## 5.1.6 Buffer Persediaan Newsvendor

Buffer persediaan dihitung menggunakan model newsvendor, bukan flat +1 std:

$$\text{Buffer}_i = z \times \sigma_{e,i}$$

di mana:
- $\sigma_{e,i}$ = standar deviasi error prediksi item $i$ (dari backtest 8 minggu)
- $z = \Phi^{-1}(CR)$ = invers CDF normal pada critical ratio
- $CR = \frac{c_u}{c_u + c_o}$ = margin hilang per stockout / (margin hilang + biaya spoilage)

Dengan parameter default (margin=3, spoilage=1) → CR=75% → z≈0,8. Buffer per item berkisar dari 0,2 cangkir (item ekor) hingga 2,8 cangkir (Kopi Susu Husgendam Ice). Total buffer mingguan: 384 cangkir (36% dari permintaan).

Pendekatan ini lebih unggul dari flat +1 std karena:
1. Menggunakan $\sigma_{error}$ (ketidakpastian model), bukan $\sigma_{sales}$ (variasi penjualan yang sebagian predictable)
2. Service level ditentukan oleh biaya operasional riil, bukan konstanta arbitrer
3. Buffer per item disesuaikan dengan volatilitas spesifik item tersebut
